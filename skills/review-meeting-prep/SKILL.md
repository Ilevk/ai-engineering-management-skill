# 평가 면담 준비

작성된 개인 평가서를 바탕으로 팀원과 매니저를 위한 면담 준비 자료를 만든다. 평가서를 만든 방법이나 다른 스킬의 설치 여부에 의존하지 않는다. 점수와 등급은 판단하지 않으며, 서술형 참고 의견의 최종 판단은 인간 매니저가 한다.

## 실행 책임과 위임

메인 에이전트는 배정, 진행 상태, 인간 확인 gate와 결과 취합만 맡는다. 원문 직접 읽기, 평가 분석, 작성·수정, 사실 검증과 메모리 쓰기를 대신 수행하지 않는다. 아래 절의 작업은 배정된 서브 에이전트가 수행한다. 이미 매니저에게 받은 확정 입력은 다시 승인받지 않는다.

- 입력 확인 역할이 평가서 버전·검토 상태, 현재·다음 기대치, 면담 순서와 필요한 추가자료를 확인해 보고한다. 추가 원문 수집이 필요하면 매니저가 허용한 소스와 정확한 기간·대상 범위에서 latest fast-tier 역할에 배정한다. 원문을 요약으로 대체하지 않고 실제 링크/source ID, 조회 페이지·범위·건수·누락을 기록하며 부분 수집을 전체 완료로 표시하지 않는다.
- latest top-tier 작성 역할이 팀원용 성장 피드백과 매니저용 지원·상위 매니저 논의 자료를 준비한다. 해석과 성장 제안은 참고 의견으로 구분한다. 작성자와 별도의 latest top-tier 검증 역할이 평가서·제공된 원문 및 기대치와 대조해 사실, 개인 귀속, 자료 누락과 제안의 근거를 검증한다. 같은 작성자의 재독을 독립 검증으로 표현하지 않는다.
- 인간 검토 이후 실제 피드백과 직접 수정한 현재 파일을 top-tier 작성 역할이 다시 읽고 비교해 최종본에 반영한다. 별도 top-tier 검증 역할이 변경과 영향을 받은 부분을 재검증한다. 메인은 지적을 작성 역할에 재배정하고 미확인 내용과 질문을 취합한다. 검증 불가 내용은 확정된 사실로 바꾸지 않는다.
- 작성 선호·면담 순서의 메모리 기록과 실제 저장은 서브 에이전트에 맡긴다. 메모리에는 개인 자료를 제외하고 매니저가 지정한 위치·범위와 실제 환경의 쓰기 규칙을 따른다. 문서 저장도 현재 허용된 위치와 권한 범위 안에서 수행하고, 별도 검증 역할이 readback으로 실제 반영 여부를 확인한다. 외부 연락·전달·제출 권한은 아래 명시 요청 규칙을 그대로 따른다.

현재 런타임이 제공하는 모델 목록 또는 tier 별칭으로 역할에 맞는 지원 모델을 선택한다. tier 별칭이 없으면 존재하지 않는 별칭을 실행했다고 가정하지 않고 실제 지원 모델을 확인한다. 역할별 에이전트 ID, 요구 tier, 실제 사용 모델명, 입력·산출물과 검증 상태를 해당 회차에 기록한다. 모델명이나 최신 여부를 확인할 수 없으면 한계를 명시하며 오래된 모델명을 고정하지 않는다. 필요한 도구·모델·독립 서브 에이전트가 없으면 정확히 보고하고 인간이 변경을 허용하기 전에는 메인의 직접 수행이나 다른 방식으로 우회하지 않는다.

## 입력과 면담 방식 확인

- 대상자, 평가 기간, 사용할 평가서 버전과 검토 상태를 확인한다. 평가서에 미해결 질문이 있다면 확정된 사실과 구분한다.
- 현재와 다음 Job Level 요구사항은 매니저가 제공한 자료를 사용한다. 없는 레벨 요구사항을 만들어내지 않는다.
- 팀원의 현재 레벨은 매니저에게 제공받는다. 회사나 팀에 레벨별 정의가 없다면 매니저와 현재 수준 및 다음 수준의 기대치를 논의해 확인한 뒤 준비한다. 평가서 작성 과정에서 이미 합의한 기대치가 있으면 이를 사용하며 불필요하게 다시 정의하지 않는다.
- 매니저의 면담 순서를 메모리에서 확인하고 이번 요청과 맞는지 확인한다. 기록이 없으면 매니저에게 선호하는 순서가 있는지 묻는다.
- 매니저의 별도 순서가 없으면 아래 기본 순서를 사용한다. 면담 순서는 매니저별 장기 메모리에 기록해 다음 회차에 활용한다.
- 결과물 형식과 작업 위치는 매니저의 요청을 따른다. 실제 평가서와 면담 준비 자료를 스킬 저장소에 저장하지 않는다.

## 팀원에게 전달할 성장 피드백

- 현재 Job Level에서 기대하는 수준을 달성하고 있는지 평가서의 사실, 매니저의 판단과 제공된 요구사항을 연결해 정리한다.
- 다음 Job Level로 성장하기 위해 더 보여줘야 할 역량과 노력할 부분을 제공된 요구사항에 따라 제안한다.
- 이미 입증한 역량, 아직 부족한 근거와 앞으로의 행동 제안을 구분한다. 평가서에 근거가 없다는 이유만으로 역량 부족을 확정하지 않는다.
- 새로운 성장 관련 해석이나 행동 제안은 매니저 검토용 참고 의견으로 표시한다. 새로운 실적, 팀원의 의도, 점수나 승진 결정을 추가하지 않는다.

## 매니저의 지원과 상위 매니저 논의

- 팀원에게 제안할 성장 방향과 그 성장을 위해 매니저가 제공해야 할 지원을 연결해 정리한다.
- 팀원이 다음 Job Level의 역량을 보여줄 수 있도록 매니저가 상위 매니저와 논의해야 할 사항과 추진할 노력을 제안한다.
- 제안된 지원이나 기회를 이미 승인된 결정으로 표현하지 않는다. 매니저가 직접 수행할 일과 상위 매니저의 논의 또는 결정이 필요한 일을 구분한다.
- 매니저용 준비 자료와 팀원에게 전달할 내용의 범위는 매니저가 정한다.

## 기본 면담 순서

1. 매니저가 검토한 최종 평가서를 팀원에게 전달한다.
2. 전달 후 1주일 이내에 1 on 1 면담을 진행한다.
3. 면담에서 나온 피드백과 이의를 기록하고, 매니저의 확인과 판단을 거쳐 최종 평가서에 반영한다.
4. 면담 반영본을 확인한 뒤 최종 평가서를 제출한다.

이 순서는 매니저가 정한 별도 순서가 없을 때만 사용한다. 준비 단계에서 전달, 면담, 합의, 수정이나 제출이 이미 이루어졌다고 기록하지 않는다. 전달일이 확인되면 그 날짜를 기준으로 면담 기한을 계산한다.

실제 팀원 전달, 일정 초대, 상위 매니저 연락과 제출은 해당 행동을 명시적으로 요청받은 경우에 수행한다. 준비 자료를 작성하라는 요청만으로 다른 사람에게 메시지를 보내지 않는다.

## 피드백 반영과 메모리

- 실제 면담 피드백과 이의는 매니저가 제공한 내용이나 허용한 기록을 사용한다. 예상 반응을 실제 답변으로 기록하지 않는다.
- 사실 정정, 평가 해석에 대한 이의와 성장 지원 합의를 구분한다. 이의 제기 자체를 기존 사실이 틀렸다는 확정으로 취급하지 않는다.
- 매니저가 확인한 수정 내용을 최종본에 반영하고, 반영 내용과 남은 이견을 매니저가 검토할 수 있게 남긴다.
- 직접 수정이 있을 수 있으므로 현재 평가서를 다시 읽은 뒤 수정한다. 저장했다면 다시 읽어 실제 반영 여부를 확인한다.
- 장기 메모리에는 매니저별 작성 선호와 면담 순서만 저장한다. 개인별 평가, 정정 사실과 면담 내용은 해당 회차 기록으로 관리한다.
- 로컬 또는 리모트 메모리는 매니저가 지정한 위치와 현재 환경의 쓰기 규칙을 따른다. 선호가 변경되면 적용 범위와 갱신 시점을 함께 기록한다. 다음 회차의 사실 근거로 개인별 기록을 자동 재사용하지 않는다.
- 현재 요청은 이전 선호보다 우선한다. 메모리 위치나 사용 범위가 미정이면 확인하고, 저장 실패를 저장 완료로 보고하지 않는다.
