# 위임 조사 파이프라인과 독립 검증

착수 소스 탐색부터 이 문서를 사용한다. 메인은 배정, 진행 상태, 인간 확인 gate, 검증 결과 취합과 수정 재배정만 수행한다. 원문 수집, 그룹핑, 평가 초안 작성과 직접 사실 검증은 별도 서브 에이전트에게 맡긴다. 매니저 수정 반영과 최종본 변환·readback도 작성자와 별도 검증자에게 배정한다.

## 역할과 실행 기록

현재 런타임이 제공한 모델 목록 또는 tier 별칭에서 latest fast-tier와 latest top-tier 역할에 해당하는 지원 모델을 확인한다. tier 별칭이 없으면 존재하지 않는 별칭을 실행하지 말고 실제 지원 모델을 확인·기록한다. 선택한 모델이 최신인지 확인할 수 없으면 그 한계도 기록하고 요구를 충족했다고 단정하지 않는다. 오래된 특정 모델명으로 고정하지 않는다. 역할별 에이전트 ID, 요청한 tier, 실제 사용 모델명, 입력 범위, 산출물 위치와 검증 상태를 해당 회차에 기록한다. 실제 모델명을 확인할 수 없으면 미확인으로 보고하며 임의로 채우지 않는다. 필요한 tier, 조회 도구 또는 독립 에이전트가 없으면 인간에게 정확한 제한과 영향을 알리고 변경 허용을 받기 전에는 다른 모델·도구·메인의 직접 수행으로 우회하지 않는다.

| 단계 | 실행 역할 | 입력과 산출물 |
| --- | --- | --- |
| 착수 소스 탐색 | 소스별 탐색 에이전트 | 제공된 MCP/plugin/connector의 실제 위치, 조회 기능, identity 및 날짜 규칙, 접근 한계 |
| 원문 수집 | latest fast-tier 수집 에이전트 | 확인된 범위의 원문 로컬 파일과 소스별 수집 manifest |
| 수집 검증 | 수집자와 별도 검증 에이전트 | 원문, 조회 결과와 manifest를 대조한 누락·완료 여부 |
| 팀 목표별 그룹핑 | latest top-tier 그룹핑 에이전트 | 검증된 원문에서 업무 흐름과 개인 기여를 유지한 목표별 근거 묶음 |
| 그룹핑 검증 | 그룹핑 작성자와 별도 검증 에이전트 | 원문에 기반한 귀속·누락·중복·해석 검증 |
| Markdown 초안 | 그룹핑 작성자와 별도의 latest top-tier 초안 에이전트 | 검증된 근거 묶음과 매니저 요구사항에 따른 개인별 초안 |
| 초안 검증 | 초안 작성자와 별도 검증 에이전트 | 원문까지 역추적한 사실·해석·기간·개인 역할·요구사항 검증 |

탐색, 수집, 수집 검증, 그룹핑, 그룹핑 검증, 초안, 초안 검증을 별도 역할로 배정한다. 같은 산출물의 작성자 재독은 독립 검증이 아니다. 검증자에게 작성자의 결론만 주지 않고 원문과 범위도 제공한다. 단계별 수정은 작성자에게 재배정하고 영향을 받은 내용은 검증자가 다시 확인한다. 착수 확인 이후 범위 안의 조사·검증마다 인간 승인을 다시 받지 않는다. 새 소스나 기간 확대는 매니저에게 확인한다.

## 소스 탐색과 착수 확인

탐색자는 매니저가 제공한 소스만 읽기 전용으로 확인한다. 실제 프로젝트·채널·문서 제목과 링크, 접근 가능 범위와 검색 제한을 보고한다. 메인은 이를 취합해 기간, 대상, 팀 목표와 기대치와 함께 착수 확인을 받는다. 탐색 단계에서 본격 수집을 시작하지 않는다.

소스별로 기간 필터에 사용할 날짜(생성·수정·완료·댓글·메시지 날짜 등), 시간대, 종료 경계를 확인한다. 원문 작성일과 실제 업무 시점은 별도로 유지한다. 팀원 identity, 계정 ID와 alias, collaborator 필드 또는 관계의 실제 의미와 매칭 규칙을 확인한다. 소스별로 다른 날짜·collaborator 의미를 임의로 같게 취급하지 않는다. 필요한 날짜·identity·매칭 기준이 불명확하면 이를 확인한 뒤 수집한다.

제품명은 예시다. 이슈 관리, 대화, 문서와 회의 기록 등 매니저가 제공한 범주의 실제 도구를 조사한다. Jira/Slack/Notion/Google Docs를 필수로 요구하지 않으며 Linear/Teams/Obsidian 등으로 대체될 수 있다. 접근 가능한 모든 자료를 입력으로 확대하지 않는다.

## 원문 수집과 범위 추적

확인된 범위의 원문 정보를 로컬 임시 파일에 수집한다. 요약으로 원문을 대체하지 않는다. 해당 회차의 허용된 작업 위치에 소스별·월별로 보관하며, 민감한 원문이나 개인별 산출물을 공개 스킬 저장소, 스킬 예시 또는 Git 이력에 넣지 않는다. 특정 자동화나 고정 파일 형식은 요구하지 않지만 원문과 출처를 재조회·대조할 수 있어야 한다.

- 이슈 관리 예시: Jira에서 팀원이 Assignee 또는 확인된 collaborator 조건에 해당하는 모든 티켓을 월별 폴더에 저장한다. 본문과 메타데이터뿐 아니라 **코멘트 내용도 전부** 수집한다. 티켓 목록 pagination과 각 티켓의 코멘트 pagination을 각각 끝까지 순차 조회한다. 각 코멘트의 원문, 작성자, 작성·수정 시각 등 제공되는 시각, 실제 링크 또는 source ID를 보존한다. 기간에 속하는 티켓과 댓글의 포함 규칙은 착수에서 확인한 날짜 규칙을 따른다. 범위를 벗어난 개인 자료를 임의로 확장 조회하지 않는다.
- 대화 예시: Slack에서 확인된 팀원 identity/alias에 대한 언급 전체와 업무 흐름을 이해하는 스레드·전후 문맥을 월별로 수집한다. 조회 API의 검색 제한이나 잘린 스레드를 기록한다.
- 문서 예시: 제공된 Notion의 Tech Spec, ADR, Meeting Notes와 관련 하위 자료를 수집한다. Google Docs의 Gemini 회의 노트도 제공된 경우 같은 원칙으로 수집한다. 파일과 블록의 조회 한계, 접근 실패를 보존한다.

소스별 manifest에 다음을 남긴다: 조회 범위와 필터·identity·날짜 기준, 실행 시각, 페이지/커서 순서와 다음 페이지 유무, API가 제공하는 예상 총수와 실제 조회·저장 건수, 티켓별 댓글 수와 페이지 완료 여부, 각 페이지와 댓글별 원문 저장 여부 및 원문 파일과 실제 링크/source ID의 대응, 중복 처리, 실패·접근 불가·누락 항목과 재시도 결과. 총수 미제공이면 알 수 없다고 적는다. 링크를 얻지 못했으면 source ID와 링크 미확보 상태를 남기며 링크를 만들지 않는다.

일부 페이지, 코멘트 또는 원문이 빠졌거나 API 제한으로 전체 범위를 증명하지 못하면 완료 또는 전체 수집이라고 보고하지 않는다. 부분 수집 상태와 확인 가능한 범위를 기록한다. 수집 검증자는 조회 결과와 manifest를 대조해 페이지 종료, 건수, 티켓별 댓글 포함, 날짜·identity 범위와 원문 보존 여부를 확인한다. 표본 확인만으로 전체 수집을 보증하지 않는다. 부분 수집이어도 확인된 근거는 후속 단계로 전달하고 누락의 영향과 확인 질문을 함께 유지한다.

## 티켓 기반 GitHub 조사

코드베이스 확인이 필요한 경우 수집 역할은 Jira 등 업무 관리 도구의 티켓을 출발점으로 GitHub를 조사한다. 티켓의 연동 정보, 본문과 코멘트에 있는 PR·커밋 링크를 따라 관련 코드 변경을 확인한다. GitHub가 허용된 자료 범위에 없거나 관련 저장소가 불명확하면 필요한 조회 범위를 매니저에게 확인한 뒤 진행한다. 이미 허용된 범위는 다시 승인받지 않는다.

- 직접 연결된 링크가 없으면 허용된 GitHub 저장소 안에서 티켓 key·식별자로 관련 PR·커밋을 검색한다. 검색 결과와 티켓의 업무 내용을 대조해 연결 관계를 확인하며, 식별자 일치만으로 동일 업무나 개인 기여를 확정하지 않는다.
- PR의 실제 diff와 필요한 주변 코드를 해당 커밋 기준으로 확인한다. 작성·리뷰·협업 역할, 업무 시점과 병합 상태를 함께 확인하고 티켓 담당자라는 이유만으로 코드 변경 전체를 개인에게 귀속하지 않는다.
- 원문과 함께 티켓–PR–커밋 관계, 실제 링크, 커밋 SHA와 확인한 코드 경로·행 번호를 로컬 파일과 manifest에 남긴다. 접근 실패, 잘린 diff와 미확인 연결은 누락으로 기록하며 전체 저장소·다른 대상자·기간으로 조사 범위를 자동 확대하지 않는다.
- 별도 검증 역할이 티켓과 코드 변경의 연결, 개인 역할·기간, 원문 보존과 조회 범위를 대조한다. 확인되지 않은 내용은 평가 근거에서 제외하고 실제 확보한 근거와 매니저 확인 질문을 남긴다.

## 목표별 그룹핑

별도의 latest top-tier 에이전트가 검증된 원문을 팀 연간·분기 목표별로 묶고 평가에 필요한 주요 기여를 추린다. 요약 과정에서도 업무의 발단·결정·협업·진행·결과, 해당 개인의 역할과 구체적 기여, 사건 시점, 원문 파일/링크/source ID와 검증 상태를 유지한다. 계획, 진행, 완료, 실제 성과를 구분한다.

목표와 연결이 확인되지 않는 업무는 별도로 두며 억지로 귀속하지 않는다. 팀 성과를 개인 성과로 바꾸지 않는다. 같은 업무의 여러 출처는 보완 근거로 묶고 성과를 중복 계산하지 않는다. 누락 또는 자료 부재를 역량 미달로 바꾸지 않는다. 충돌하는 주장과 미확인 내용은 평가 근거에서 제외하고 실제 확인된 링크와 매니저 질문으로 남긴다. 링크도 없으면 미확보라고 밝힌다.

그룹핑 검증자는 원문과 대조해 중요한 기여나 반대 근거의 누락, 팀 목표와의 관계, 개인 귀속, 숫자·날짜·인용, 중복과 업무 흐름의 왜곡 여부를 점검한다.

## 초안 작성과 교차검증

그룹핑 작성자와 별도의 latest top-tier 에이전트가 검증된 조사·그룹핑 결과를 받아 개인별 MD 초안을 작성한다. 필요하면 허용된 원문을 확인하되 새로운 조사가 필요하면 메인에게 수집 역할 재배정을 요청한다. 확인된 사실, 매니저 판단, 에이전트의 서술형 참고 의견과 미해결 질문을 구분한다. 현재·다음 Job Level 관계는 제공되거나 합의된 기대치에만 연결하고 점수·등급을 산정하거나 추천하지 않는다.

초안 검증자는 문장을 원문까지 역추적해 실제 링크, 숫자·날짜·인용, 업무 상태, 개인 역할, 기간과 제공된 기대치에 맞는지 확인한다. 에이전트가 검증했다는 주장을 원문 근거의 대체물로 쓰지 않는다. 직접 열지 못한 링크를 확인됐다고 하지 않는다.

각 검증 결과는 확인됨, 정정 필요, 확인 불가로 구분하고 근거와 영향을 남긴다. 새 근거 없이 같은 불일치가 반복되면 중단하고 확인 불가로 유지한다. 미확인 내용은 평가 근거에서 제외하되 확인된 내용으로 초안을 계속 작성한다. 메인은 검증 결과와 실제 확보한 근거 링크 및 확인 질문을 취합해 매니저에게 전달하고 직접 사실 판정을 대신하지 않는다. 조사·검증·수정 이력은 해당 평가 회차에만 보관한다.
