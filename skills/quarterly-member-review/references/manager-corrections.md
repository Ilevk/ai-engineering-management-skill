# 매니저 수정과 메모리

매니저가 초안을 직접 수정하거나 인터뷰로 정정할 때 사용한다. 메인은 수정 반영을 초안 작성 에이전트에, 재검증을 별도 검증 에이전트에 배정하고 결과만 취합한다. 아래 읽기·비교·반영은 배정된 역할이 수행한다.

## 수정 반영

1. 수정 직전의 초안과 현재 파일을 읽고 달라진 부분을 비교한다.
2. 사실 정정, 서술형 판단 변경과 작성 선호를 구분한다.
3. 매니저가 지적한 사실은 정정 근거 또는 매니저가 확인한 내용이라는 출처를 남겨 해당 회차에 반영한다.
4. 에이전트의 원래 문장, 매니저의 변경과 변경 이유를 해당 회차의 수정 기록으로 남긴다. 이유가 분명하지 않으면 인터뷰로 확인하며 임의로 일반화하지 않는다.
5. 관련 평가 문장과 참고 코멘트를 수정하고 다시 확인한다. 매니저가 제공한 최종 판단은 에이전트의 제안보다 우선한다.

## 장기 메모리 범위

장기 메모리에는 매니저의 작성 선호와 면담 순서만 저장한다. 예를 들어 문장의 길이, 강조 방식이나 선호하는 면담 진행 순서가 실제 수정과 설명에서 확인된 경우에 해당한다.

개인별 사실 정정, 개인에 대한 평가 판단, 원문 자료와 분기별 실적은 해당 회차 기록으로 남긴다. 이 내용을 다음 회차의 사실 근거나 지속적인 개인 특성으로 재사용하지 않는다.

저장 위치는 현재 환경의 로컬 또는 리모트 메모리 중 매니저가 지정한 곳을 따른다. 위치나 사용 범위가 정해지지 않았으면 확인한 뒤 저장한다. 현재 환경의 메모리 쓰기 규칙과 사용자 권한을 따른다.

기록은 매니저를 구분하고 선호 내용, 적용 범위, 변경 이유와 갱신 시점을 포함한다. 일회성 문서 수정을 일반적인 선호로 확정하지 않는다. 다음 회차에 적용할 수 있는지 불명확하면 매니저에게 확인한다.

다음 회차에는 관련 메모리를 읽되 이번 요청을 우선한다. 기억한 선호가 바뀌면 해당 메모리의 갱신 규칙에 따라 새 내용을 반영한다. 작성 선호를 근거의 사실 여부, Job Level 요구사항이나 점수 판단의 대체물로 쓰지 않는다.

저장이 실패하면 저장되었다고 보고하지 않는다. 확인된 선호와 아직 저장되지 않은 내용을 구분해 알리고, 개인별 자료를 다른 위치에 임의로 복사하지 않는다.
